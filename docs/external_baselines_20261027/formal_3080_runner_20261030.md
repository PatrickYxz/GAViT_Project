## 实验问题与边界

- 问题：在既有NWPU20% pool/80% test划分，披露配置的DFAGCN独立实现seed42能达到什么OA、macro-F1、逐类准确率，增加多少成本；结果用于外部方法对比及独立实现限制讨论。
- 主变量是方法，沿用既有manifest、45类、5040train/1260val/25200test。GPU换为本次用户取得的RTX3080 10GiB，UUID固定GPU-70be4364-0641-e89d-828e-78727c6001ec，资源和效率单列。单seed不能证明稳定优势，不能冒充原作者官方实现或论文分数复现。
- 便宜门禁已完成：实际4090 360/90一轮及新3080 VGG batch1/图batch100更新。本次不重复这些检查。正式pipeline原API已在合成实际算子链验证。
- 模型、seed42、图batch100、VGG batch1、最多100轮、Adam/StepLR、九个C值、FP32/关闭AMP和TF32不变。完整配方必须与交付固定JSON逐字节一致。
- 验证CE选epoch、验证OA选C（平局小C），fresh6300 refit后才提取并评估完整test；不从旧450样本学得权重续训，不混用旧4090特征缓存。
- 单批时间不足以估计全流程费用；日志保存每轮实际时间/吞吐，首轮后可据实估算。租赁费率未知则不编造费用。

## 入口和接口

- 新建tools/run_dfagcn_nwpu_formal.py；stdlib-only inspect检查指定空闲3080、manifest完整SHA/counts、完整权重SHA、完整配方SHA、依赖版本及本机LIBLINEAR可执行文件、数据源和可用磁盘。
- 复用tools/probe_dfagcn_gpu.py的GPU/runtime方法和tools/run_dfagcn_nwpu_smoke.py的数据验证/恢复方法；交付器extra_members显式嵌入两个只读依赖，不修改旧入口。旧recover_selected仅适用于pool并记录test0；完整test恢复须独立实现正确记录test数量。
- build_bundle(..., extra_members=())接收仓库内相对路径列表，拒绝目录、非法路径、符号链接、重复/覆盖入口或已有payload；默认保持旧包兼容。
- 正式run要求显式UUID，独立新output，重新核验资源。每阶段保存source/recipe/runtime/command/二进制身份、SHA、计时、峰值显存；持续显示真实VGG首batch和阶段进度；后台stdout和run.log均可读。
- 顺序：新pool_cache6300 → train_cache5040/val_cache1260切片 → calibrate(mode=formal) → fresh refit6300 → 新test_cache25200 → evaluate。调用pipeline原API，不添加新优化/指标选择规则。
- 原图可用时逐SHA验证；否则仅从已校验持久ZIP恢复所需阶段图片到新output内。pool阶段不恢复test；test恢复仅在refit完成后。不得写旧数据目录、旧缓存、旧checkpoint。恢复代码限制ZIP路径和成员SHA，不用extractall。
- output已存在时拒绝；不声称支持epoch断点恢复。失败保留cache、history、failure.json/traceback/run.exit，下次再根据实际失败选择缓存复用，不能悄悄重启或覆盖。正常COMPLETE只在正式test/指标/最佳与最终checkpoint/配置/身份/exit均落盘后打印。summary不含全预测/矩阵，只给指标及文件路径。
- inspect打印固定UUID的完整run_command和nohup后台命令；不只凭PID认定启动成功，日志应有设备、首个VGG/图batch。status只读显示简短进度/完成摘要，不输出大矩阵。
- 磁盘检查报告float32缓存最低字节和可用磁盘，保守门禁40GiB（含重复train/val缓存、九C的文本中间文件、test文本、按需图片）；明确这是容量门禁而非性能实测。失败阶段不自动清理。
